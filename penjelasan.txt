STATUS DEPLOY: Vercel (vanilla Node.js serverless)

===============================================
MASALAH YANG SUDAH DIPERBAIKI
===============================================

[S1] Serverless function crash di Vercel
     Penyebab: fs.writeFileSync() dan fs.mkdirSync() tanpa try-catch,
               filesystem deployment directory read-only di Vercel.
     Solusi: Semua operasi fs dibungkus try-catch.
             Storage ditulis ke /tmp (writable di Vercel).

[S2] CSS tidak load saat deploy ke Vercel
     Penyebab: vercel.json routes semua request ke server.js (catch-all).
               Vercel serverless tidak include file statis dalam bundle.
               server.js tidak bisa baca file CSS/HTML dari filesystem.
     Solusi: Hapus builds di vercel.json, pakai rewrites only untuk /api/*.
             Buat api/index.js sebagai entry point Vercel.
             Vercel auto-serve file statis (HTML, CSS, JS) dari root.

[S3] Warna website diganti ke biru tua
     Accent: #64ffda (teal) -> #4da6ff (biru)
     Semua rgba(100,255,218,...) -> rgba(77,166,255,...) di semua file.

===============================================
MASALAH YANG MASIH ADA (BELUM DIPERBAIKI)
===============================================

[M1] KEAMANAN: Password admin hardcoded di client-side
     Lokasi: pengunjung.html (JS: PASSWORD='devcode')
     Risiko: Siapapun bisa lihat password di View Source.
     Saran: Pindahkan autentikasi ke server-side (API endpoint).

[M2] KEAMANAN: Bot token & chat ID di .env
     Risiko: Jika repo public, token Telegram bocor.
     Saran: Hapus .env dari repo, gunakan Environment Variables
             di Vercel Dashboard (Settings > Environment Variables).

[M3] Data tidak persisten di Vercel
     Masalah: /tmp hilang saat cold start function.
    database.json dan foto selfie terhapus antar request.
     Saran: Gunakan external database:
       - Supabase (PostgreSQL, gratis tier generous)
       - Firebase Firestore (NoSQL, real-time)
       - Upstash Redis (serverless-friendly)

[M4] Visitor data overwrites (bukan accumulate)
     Masalah: Jika IP sama, data lama diganti (bukan ditambah).
     Lokasi: Backend/server.js saveVisitor() line ~194
     Saran: Simpan semua kunjungan, jangan replace. Tambah field
             visitCount atau push ke array visits[].

[M5] Race condition di saveVisitor()
     Masalah: Read-modify-write tanpa locking.
               2 request bersamaan bisa corrupt database.json.
     Saran: Pakai atomic write atau external DB (lihat M3).

[M6] Tidak ada rate limiting
     Risiko: Bot bisa flood /api/track-ip, /api/send-selfie,
             /api/send-telegram untuk abuse.
     Saran: Tambah rate limiter per IP (misal: max 10 request/menit).

[M7] Selfie base64 bisa melebihi MAX_BODY_SIZE
     Masalah: Foto kamera resolusi tinggi + base64 encoding
               bisa > 5MB (MAX_BODY_SIZE).
     Saran: Compress foto di client-side sebelum kirim
             (canvas.toDataURL('image/jpeg', 0.6)).

[M8] Selfie files accumulate tanpa cleanup
     Masalah: Foto tersimpan di /tmp/data/selfies/ tanpa batas.
     Saran: Hapus foto lama atau batasi jumlah file.

[M9] Tidak ada Content-Length validation di selfie
     Risiko: Request besar bisa exhaust memory serverless.
     Saran: Validasi ukuran buffer setelah base64 decode.

[M10] Telegram caption tidak sanitize HTML
     Risiko: Injection HTML/formatting via parameter 'name'.
     Lokasi: Backend/server.js sendTelegramPhoto()
     Saran: Escape HTML di name sebelum masukkan ke caption.

[M11] Static file serving return 200 untuk semua 404
     Masalah: File tidak ditemukan = serve index.html (200 OK).
     Saran: Return 404 status code untuk file tidak ditemukan.
